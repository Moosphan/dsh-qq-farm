## 已验证的事实

### 收获
- 多株成熟 → 点底部「一键收获」按钮，一次收完（实测 13 株）
- 单株/多轮作物 → 点作物唤出「手」→ 点「手」收一轮 → 手消失 → 重复
- 成功判据：出现「总价值 x万 / 经验值 +N」，或「可摘」消失

### 种植
- 「一键种植」是**开关**：点击弹确认框（`提示信息` → 取消/确认），确认后生效
- 确认弹窗文字 **OCR 读不到**（遮罩），只能靠"弹窗消失"判断
- 勾选后点空地 → 底部弹出**种子栏**（图标 + 数量角标，如 16/1/18/30/897）
- 选中某个种子 → **自动种满所有空地**

### 活动
- 活动页路径：点「奶茶热销中」图标 → 奶茶小铺页 → 底部「兑换商店」→ 顶部「种子」
- 活动页特征文字：`店铺等级 / 奶茶小铺 / 营业额 / 倒计时`
- ⚠️ 不是底部导航的「商城」，两者图标紧挨着
- 兑换流程：点种子卡片 → 弹「兑换」详情（成熟/果实/季产/收入）→ 点绿色「兑换」→ 扣款 → 「恭喜获得」
- 返回箭头在 **(85,225)**，不是标题栏 (60,155)

## 架构改进建议（重要）

把「种植」做成 Agent 端原子操作，避免模型多轮往返：

```
POST /v1/instances/:id/plant  {seed: "event" | "auto"}
  内部：截图 → 找空地 → 点空地 → 等种子栏 → 选种子 → 点击 → 验证
  返回：{ok, planted: N, seedUsed: "森野黄金芽"}
```

理由：一次完整种植需要 5~6 次截图与点击，模型逐步驱动成本高（每轮耗时且耗 token）。
机械流程下沉为原语，符合 v2 的"插件做手脚、模型做判断"分工。
