# 田地晶格定位问题 — 交接说明

> 用途：`cvhelper.py` 格子定位问题的来龙去脉 + 现状。
> **现状：已修复（2025-10-23 两轮）**：① 原点是搜索拟合出来的，不再用 bbox；
> ② 坐标定位改成**与土地颜色无关**（用草地/边线几何），土地升级换土色也不失效。

## 状态：已修复

`fit_field()` 的定位**不依赖土块颜色**（升级后是黑土/红土/沙土都无所谓）：

| 步骤 | 做什么 | 为什么不吃颜色 |
|---|---|---|
| 1 | `field_region()`：草地之外的**最大连通块** = 整块田地（填掉内部空洞） | 草地是场景底色，不随土地皮肤变 |
| 2 | `cell_components()`：强边缘把画面切块，取「填充率≈0.5、长宽比≈2」的菱形块 = 格子内部 | 菱形形状与颜色无关（矩形图标填充率≈1，会被排除） |
| 3 | 候选原点 = 检出格心 − i·u − j·v，把 4×6 方块在画面上挪一遍 | — |
| 4 | 选一块：内点最多 > 24 格心都在田地区域内 + 外侧 20 个探针都在区域外 > 离田地先验最近 | 外侧探针是**整块**几何证据，专治晶格整格平移 |
| 5 | 等轴测约束最小二乘：u=(2a,a)、v=(−2a,a)，只拟合 (x0,y0,a) | a 就是「田地被切成 4×6 的格宽」，由检出格子间距反算 |

`fit` 里的 `method` 说明这次靠什么定的：

| method | 触发条件 | 精度 |
|---|---|---|
| `shape` | 检出菱形格子 ≥4 个（正常情况） | 0.5~3px |
| `cache` | 几何证据不足，但 `~/.dsh-farm/lattice-<W>x<H>.json` 有货 | 同上一次 |
| `search` | 什么都检不出（如整片被大作物完全盖住） | 退回旧的土壤颜色拟合，几 px |
| `blobs` | 仅用土壤色地块（旧路径，兜底） | ~1px |

三态分类也做了兼容：土色不是棕色（|R−G| 很小）时改看结构 —— 均匀浅绿=未开垦、
格心有绿=作物、格内结构复杂=作物、否则=空地。现行棕色皮肤的判定完全不变。
`macagent._cv_cells()` 现在优先用 cvhelper 的 `kind`，退回纯 RGB 判定的老逻辑。

已知局限（真要改再看）：

- **整格平移歧义**：晶格是周期的，把 4×6 方块整体挪一格，格子本身依然对齐
  （只要还在田里）。所以"哪一块是田地"必须靠整块田地的证据（外侧探针）或
  田地位置的先验（`PRIOR_ORIGIN` + 缓存）。田地在一局内位置固定，实测 8 张
  截图互差 <4px，先验只当"平票时的裁判"。
- 整片被大作物完全盖住时（`sim_planted`）菱形块被切断 → 宁可返回 `ok:false`，
  让 macagent 回退 `_sample_cells`，不给一个可能偏一格的坐标。
- `field_region` 假设"田地外沿 = 草地"：如果以后出现把田地包在木地板里的场景，
  这条会失真（目前只有田地是这种被草地包住的整块）。
- 分类里的 `grass/bigcrop` 仍依赖"整格偏绿"；绿土皮肤的极端情况未验证。

踩过的细节（改之前先看这里）：

1. **不要用颜色定坐标**：第一版靠"格心必须是土壤色"，能对上但不是颜色无关；
   现在坐标走几何，颜色只用于三态（而且只在棕色皮肤下作为强判据）。
2. **土坑/作物长在格心上**，会把"落在耕地上的比例"这种打分带偏（会为了躲土坑
   偏 15~20px、为了躲作物偏一格）。→ 打分改成"内点数 + 整块田地吻合"。
3. **建筑地板是木色**，和土壤几乎一样；靠「田地外侧一圈」+「田地区域面积
   20~60 格」挡掉（小铺页整片木地板面积 ≈220 格，直接否掉）。
4. 6 参数最小二乘会把 u/v 拟歪（一行错位一路放大）→ 压成等轴测 3 参数。
5. 下面「已尝试且失败的方案」是历史记录，**不要**再回头用 bbox 锚定。

## 问题（历史）

`agent/mac/cvhelper.py` 算出的 24 个格子中心**整体偏移**，落在草地与建筑上，
而不是落在田地的棕色菱形内。导致：
- `plant` 找不到真实空地
- 点击坐标打到奶茶小铺（会跳到活动页）

## 已尝试且失败的方案

1. `minAreaRect` 求田地平行四边形 → 轴对的是菱形**对角线**（56°/146°），不是格子边
2. 用检出地块中心当原点 → 原点随机，误差累积
3. `field_bbox`（土壤+边框）锚定 → 边框色把建筑算进来，整体右移
4. 改成纯土壤 bbox + 公式 `x0 = fx0 + 6*|u.x|` → **方向算反，仍然偏移**
   - 实测：soil bbox 左边≈136，算得 x0≈472，而格子应覆盖 176~624

## 建议的解法（已实现，现作为兜底）

第一轮按这个方案实现（`search` / `blobs` 分支，仍然保留）：

```
在土壤掩膜内搜索 (x0, y0)，使 24 个格心
   x = x0 + 56*(i-j),  y = y0 + 28*(i+j)   (i in 0..3, j in 0..5)
落在"耕地像素"上的比例最大
```

判据：**格心必须是土壤色或格心土坑**（建筑、草地都不是）。

后来因为「土地升级会换土色」改成几何优先（见开头），这条只在
「一个菱形格子都检不出」时兜底。实现：`fit_field()` 的 `search` 分支、
`search_origin()`、`_plateau_center()`、`outside_frac()`。
