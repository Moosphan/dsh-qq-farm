# QQ 农场功能清单与优先级

> 参考 `qq-farm-copilot` 的已实现功能，按「用户价值 × 实现成本 × 风险」重排，
> 并对齐 v2 智能体协同架构（插件提供原语，判断交给模型）。

## 分级标准

| 级别 | 含义 | 进入条件 |
|---|---|---|
| **P0** | 核心闭环，没有它插件没意义 | 必须做，且必须稳 |
| **P1** | 高频收益，风险低 | M2 内完成 |
| **P2** | 社交/扩展玩法，中等复杂 | M3 起分批 |
| **P3** | 低频、平台相关、纯运维 | 有空再做 |

风险口径：**涉及花钱或不可逆的操作一律降级**（出售/购买默认关闭，需显式开启并二次确认）。

## 本插件特有（参考项目没有的）

| # | 能力 | 价值 |
|---|---|---|
| A | **模型视觉判断** | 作物识别不靠阈值，纠正一次即改进 |
| B | **视觉词典**（`AGENTS.md`） | 领域知识可被用户直接编辑 |
| C | **Token 预算闸门** | 小时/日上限，超限降级为脚本模式 |
| D | **变化检测** | 画面没变就不唤醒模型，省 80% 调用 |
| E | **决策可审计** | 每次点击都记录「为什么」 |
| F | **面板 = 状态镜像** | 用户能看到智能体在想什么 |

## 明确不做（或最后再做）

| 功能 | 原因 |
|---|---|
| 四格作物自动种植 | 参考项目也标注「收益太低」，且识别复杂 |
| 出售类自动化 | 不可逆，误操作损失大 |
| 协议/内存注入 | 违反用户意愿，且封号风险 |

---

## 优先级判断依据

1. **收益频率**：每天能触发多次 > 每天一次 > 一次性
2. **失败代价**：只读 < 消耗道具 < 花钱 < 不可逆
3. **识别难度**：有文字标记（可摘/倒计时）> 有固定按钮 > 纯图形判断
4. **token 成本**：能用文本判断的不上图
